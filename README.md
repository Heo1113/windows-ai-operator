# Windows AI Operator

자연어로 요청한 Windows 작업을 AI가 **정해진 동작 목록 안에서** 계획하고, Windows UI Automation(UIA)으로 화면 요소를 인식해
직접 수행하는 독립 데스크톱 프로그램입니다. 사용자는 계획을 먼저 확인하고, 실행 과정을 보면서 언제든 승인·거부·일시정지·중단할 수 있습니다.

- **AI는 코드를 실행하지 않습니다.** 모델은 미리 정의된 동작(`click`, `set_text`, `toggle` …)과 인자만 JSON으로 내고, 실행기가
  스키마·안전 정책·허용 앱 목록으로 검사한 뒤 수행합니다. 목록에 없는 동작·필드는 거부합니다. PowerShell·명령 프롬프트는 쓰지 않습니다.
- **허용 앱 목록의 프로그램만** 읽고 조작합니다. 명령 실행·시스템 관리·보안·인증·암호 관리자·원격 제어 프로그램과 이 프로그램 자신은
  목록과 관계없이 차단합니다. 관리자 권한 창은 조작하지 않습니다.
- 파일 삭제·덮어쓰기·저장, 파일 이동, 설치·제거, 서비스·예약 작업, 보안 설정, 외부 전송, 인증정보, Windows 설정 변경, 초기화처럼
  되돌리기 어려운 동작은 **항상 승인**을 받습니다(끌 수 없음). 결제·구매·송금과 관리자 권한 작업은 승인과 관계없이 **거부**합니다.
  승인 창에는 대상·변경 내용·영향 범위·복구 방법이 나오고, 승인 뒤에도 **실행 직전에 대상을 다시 확인**합니다. 응답이 없으면 실행하지 않습니다.
- 비밀번호 입력란에는 입력하지 않고, 비밀번호 값은 읽지도 않습니다. API 키·토큰·카드번호 등은 로그·DB·모델 프롬프트에서 가립니다.
- 화면의 텍스트(창 제목·요소 이름·값·파일 이름)는 **신뢰하지 않는 데이터**로 감싸 모델에 보냅니다. 지시처럼 보이는 문구가 있으면
  그 작업의 모든 변경 동작을 승인 대상으로 바꿉니다.
- 모든 단계는 SQLite에 기록됩니다. 프로그램이 작업 중 종료되면 다음 실행 때 '중단/부분 완료'로 정리하고 **자동으로 다시 실행하지 않습니다.**

> 검증 상태: Linux·Windows CI에서 단위 테스트, **Windows 러너의 실제 UIA 테스트**(별도 테스트 앱과 메모장), 게시된 EXE의 GUI 스모크
> 테스트(모든 화면, 모의/실제 UIA 작업, 강제 종료 후 복구)를 실행합니다. **사용자 PC(4K·175%·다중 모니터)와 실제 Strata 모델로는 아직
> 검증하지 않았습니다.** 자세한 내용과 사용자 PC 확인 방법은 [docs/VERIFICATION.md](docs/VERIFICATION.md)를 보세요.

## 설치와 실행 (Windows 10/11 x64)

1. GitHub Actions **CI** 실행 결과의 아티팩트 `WindowsAiOperator-win-x64`를 내려받습니다(또는 아래 "소스에서 빌드").
2. 압축을 풀고 해시를 확인합니다.
   ```powershell
   Get-FileHash .\WindowsAiOperator-win-x64.zip -Algorithm SHA256
   ```
3. `WindowsAiOperator.exe`를 실행합니다. .NET 설치가 필요 없습니다(자체 포함 단일 EXE). 서명되지 않은 EXE라 SmartScreen 경고가 나올 수 있습니다.
   관리자 권한으로 실행하지 마세요(필요 없고, 일반 권한으로 실행해야 관리자 창을 건드리지 않습니다).

패키지 구성: `WindowsAiOperator.exe`(GUI), `wao.exe`(읽기 전용 진단 도구), `OperatorTestTarget.exe`(자동화 시험용 독립 앱 — 자기 화면 상태만 바뀌고
파일을 만들지 않음), `portable.txt`, 문서.

### 처음 해 볼 것 (모델 없이)

1. **워크플로** 화면에서 "테스트 앱: 카운트 증가와 텍스트 입력"을 고르고 [실행] — 테스트 앱이 열리고 버튼 클릭·텍스트 입력이 실제로 수행됩니다.
2. **창 검사기**에서 테스트 앱 창을 고르고 요소 트리에서 `카운트 증가` 버튼을 선택한 뒤 [누르기].
3. 테스트 앱의 '선택 항목 삭제' 버튼을 눌러 보면 승인 창이 뜹니다(테스트 앱 안의 목록만 바뀌는 안전한 시험).

### 데이터 위치

- 포터블 모드(기본 패키지): 실행 파일 옆 `portable.txt`가 있으면 `data\` 폴더에 저장합니다. 지우면 `%LOCALAPPDATA%\WindowsAiOperator`.
- `wao.db`(SQLite·WAL), `settings.json`, `secrets.dat`(DPAPI로 암호화한 API 키, 이 Windows 계정에서만 해독), `logs\`(비밀정보 가림), `backups\`.
- `--data-dir 경로`로 다른 폴더를 쓸 수 있습니다. 한 데이터 폴더는 한 프로세스만 씁니다.

## AI 모델 연결 (Strata 우선)

**모델** 화면에서 연결을 고르고 [연결 확인] → 서버 목록에서 모델 선택 → [이 연결을 사용]. 모델 이름은 코드에 고정되어 있지 않습니다.

| 프로필 | 기본 주소 | 비고 |
|---|---|---|
| Strata (로컬 서버 8080) | `http://127.0.0.1:8080/v1` | `strata launch` 기본 포트 |
| Strata 데스크톱 앱 (47831) | `http://127.0.0.1:47831/v1` | 앱이 47831이 사용 중이면 다른 포트를 씀 — 앱에 표시된 주소로 바꾸세요. Serving API 키가 켜져 있으면 키 설정 필요 |
| OpenAI 호환 | `http://127.0.0.1:1234/v1` | LM Studio·llama.cpp·Ollama(`/v1`)·vLLM 등 |

- 키: 없음 / 환경 변수 이름 / 직접 입력(DPAPI 암호화 저장). 키는 `Authorization: Bearer` 헤더로만 보내며 설정 파일·로그·DB에 남지 않습니다.
- 이 PC 밖의 서버(같은 네트워크·클라우드)는 프로필에서 **'외부 서버 사용'을 직접 켜야** 쓰며, 외부 서버는 https만 허용합니다. 스크린샷 외부 전송은 별도로 켜야 합니다.
- **텍스트 전용 모델**에는 UIA 요소 트리를 구조화된 텍스트로 보냅니다. **이미지 입력**은 서버가 지원을 알리거나(Strata `vision.enabled`,
  모델 목록 `input_modalities`, llama.cpp `/props`) [이미지 입력 테스트](빨강·파랑 합성 이미지 판별)를 통과한 모델에만 켜지고,
  UIA 구조가 없는 창(구조적 인식 불가)에서만 스크린샷과 좌표 클릭(`click_point`, 항상 미리보기·승인)을 씁니다.
- [응답 형식 검사]는 가상 테스트 앱 화면으로 실제 프롬프트를 보내 모델이 유효한 계획 JSON을 내는지 확인합니다(아무것도 조작하지 않음).
- 서버가 `response_format: json_schema`를 거부하면 `json_object` → 프롬프트만으로 자동 전환하고 기억합니다.
- 모델 연결이 실패해도 앱은 계속 동작합니다(워크플로·창 검사기 직접 조작은 모델 없이 사용 가능).

## 소스에서 빌드

```powershell
dotnet build WindowsAiOperator.slnx -c Release
dotnet test --project tests/WindowsAiOperator.Tests -c Release        # 단위·회귀 테스트(모의 데스크톱)
dotnet test --project tests/WindowsAiOperator.UiaTests -c Release     # 실제 UIA 테스트(Windows 데스크톱 필요)
./scripts/publish.ps1 -OutputDir dist                                 # 포터블 패키지
./scripts/smoke-gui.ps1 -Exe dist/WindowsAiOperator-win-x64/WindowsAiOperator.exe
```

.NET 10 SDK가 필요합니다. Linux에서도 전체 빌드(WPF 컴파일 포함)와 단위 테스트가 됩니다.

명령줄: `--data-dir DIR`, `--mock-desktop`(가상 데스크톱, 실제 창을 건드리지 않음), `--mock-model`(테스트용 MOCK 모델),
`--smoke-test --smoke-report DIR`, `--real-uia-smoke`. MOCK 모드에서는 화면 상단에 표시되며 그 결과를 실제 GUI 자동화 성공으로 보지 않습니다.
